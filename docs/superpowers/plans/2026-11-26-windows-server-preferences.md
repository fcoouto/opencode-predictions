# Native Windows Preferences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a native Windows OpenCode server safely read and save the existing `predictions.json` file.

**Architecture:** Keep the preferences store and TypeScript validation. Add a Windows-only filesystem backend using a fixed Windows PowerShell/.NET helper that holds Win32 handles throughout each inspection or commit. Establish native qualification on Windows CI before making a compatibility claim.

**Tech Stack:** Node.js 26 for tests, TypeScript, built-in Windows PowerShell 5.1 and .NET Framework, Win32, GitHub Actions, OpenCode V2 server `2.2.6`.

**Spec:** [`docs/superpowers/specs/2026-11-25-windows-server-preferences-design.md`](../specs/2026-11-25-windows-server-preferences-design.md)

## Global Constraints

- Local, drive-qualified NTFS only; no directory aliases through symlinks or junctions. Keep `%APPDATA%`, explicit `XDG_CONFIG_HOME`, and `%ProgramData%` meanings. Fail closed for unverified input.
- Preserve the 65,536-byte limit, existing preference and RPC formats, server-side authorization, atomic replacement, private backups, and last-writer-wins risk. Do not add save locks, migrations, new dependencies, client changes, or POSIX changes.
- Windows PowerShell must use the OS executable, no execution-policy override, fixed code separate from request data, bounded I/O, and cancellation. Do not reuse completed ACL decisions.
- Use the macOS worktree for development and regression tests. Only native, non-admin Windows runs count for ACL and server qualification. If CI cannot run, leave Windows unqualified and report the blocker; do not weaken checks to make CI pass.

## Review Focus

1. Valid paths with spaces, apostrophes, square brackets, and non-ASCII characters must remain literal and round-trip.
2. A real user profile can inherit permissions to create unrelated siblings. A default profile must work without changing its directory ACLs.
3. Unsupported descriptors, an untrusted backup reader, and a writable parent with a read-only file must not get a permissive fallback.
4. Cancellation or lost helper output after commit dispatch must not be reported as a definite refusal or cause a retry.
5. An installed package needs the same helper as the source checkout, and two clients polling must not leave helper processes behind.

### Task 2: Add the Windows backend and prove file safety

**Files:** Add `src/preferences-windows.ts`, `src/preferences-windows-script.ts`, and `tests/preferences-windows.test.ts`. Modify `src/preferences-store.ts`, `tests/host/windows-preferences.test.ts`, and the Windows workflow. Keep the PowerShell script as a bundled TypeScript string; do not add a runtime script-file search or native binary.

**Interfaces:** `readWindowsPreferences(source: string, systemPaths: readonly string[], signal: AbortSignal): Promise<WindowsSnapshot>` and `commitWindowsPreferences(before: WindowsSnapshot, systemPaths: readonly string[], next: Uint8Array, signal: AbortSignal): Promise<WindowsCommit>` from `src/preferences-windows.ts`. `WindowsSnapshot` is `{ source: string; state: "user" | "managed" | "unavailable"; writable: boolean; expected: string; bytes: Buffer; reason?: string }`. `expected` is a versioned digest of the source, verified directory identities and security, and active file identity, security, and bytes. For absence, bind the first missing component and the remaining path to the same verified directory chain; never use a constant missing-file revision. `WindowsCommit` is `{ kind: "written"; snapshot: WindowsSnapshot } | Exclude<PreferencesWriteResult, { kind: "written" }>`. `createPreferencesStore` still returns the existing interface and alone parses or edits the preference document. Only actual Windows takes the Windows I/O branch; keep simulated-platform path tests usable.

- [ ] **Write failing tests for path and helper boundaries.** `Windows roots must identify a local drive` tests `preferencesPath` with `C:\Users\Example\AppData\Roaming`, `\rooted`, `C:relative`, `\\server\share`, `\\?\C:\device`, `C:\root:stream`, and `C:\NUL.txt`; only the first is accepted. Test the helper result decoder with malformed output, >65,536 decoded bytes, unknown statuses, timeout, and an abort. Assert unverified reads are not writable and a dropped commit reply yields `failed` with `Changes may have been saved. Reopen settings before trying again.` and no retry.
- [ ] **Write failing native authorization tests.** Run against real NTFS. Assert `documentValid === false` and unchanged file bytes for foreign owner, inherited untrusted write/delete rights, unsupported descriptor, hard link, or reparse-point target. Use the elevated runner only to seed fixtures a standard user cannot create; run assertions under the same standard token as the server test. Assert `policy === "managed"` for existing or uncheckable administration. Give the backup, in separate fixtures, an untrusted reader, a second hard link, or a reparse-point target; Save must refuse and active bytes must match. Test the deny-write ACE and read-only attribute separately. In each case, assert the valid active file loads and Save returns `read_only` even though the parent permits ordinary replacement.
- [ ] **Write failing native transaction tests.** Before the first preference byte reaches a staging file, inspect its descriptor and assert no untrusted principal has data access. After Save, assert the backup is private, the active file gained no rights for any principal, and the existing directory ACL did not change. Attempt a directory swap during a pinned operation and verify the substitute's sentinel, bytes, and directory entries remain unchanged. Replace the verified empty directory with a different safe empty directory between read and commit; assert `conflict` and no artifacts in the substitute. Test stale revisions and injected failures before replacement, after commit with no readback, and after commit with different valid bytes. Check unrelated OpenCode config bytes in every case. Both postcommit failures must yield uncertainty, leave a whole document, and reject another Save with the old revision. Use test-only fault injection outside the production request protocol. Round-trip unknown members and reject a 65,537-byte file without overwriting it.
- [ ] **Observe RED.** Run `node --test tests/preferences-windows.test.ts`; run the Windows job for real metadata, write, and backup cases. Require failures for missing Windows behavior, not skipped coverage.
- [ ] **Implement Windows path and helper boundary.** Validate before normalizing: local drive, no device/stream names, no ambiguous dot/space suffixes. Use a fixed short command with the OS PowerShell executable, no shell lookup or policy bypass. Deliver the bundled script and one separate JSON request over stdin. Do not evaluate request values. Put preference bytes in base64, cap decoded preference bytes at 65,536 and wire replies at 192 KiB, and validate statuses and shapes before use. Cap each helper invocation at 1,800 ms, including startup. Abort and reap it on cancellation. If a commit was dispatched and its outcome is lost, report uncertainty, not a definite refusal.
- [ ] **Implement handle-bound snapshots and commits in the fixed helper.** Use `CreateFileW` with `OPEN_REPARSE_POINT`; open directories with `BACKUP_SEMANTICS` and without delete sharing; walk from the validated local volume through one component at a time. Base subsequent opens on the pinned volume rather than a mutable drive mapping. Get security and stable volume/file identity from the same objects used for data, using `GetSecurityInfo` and `GetFileInformationByHandleEx`. Compare raw SID/ACL data under the spec's owner and inherited-grant rules. Distinguish directory rights to create siblings from rights to delete or replace existing entries. Require a true missing result for absence and check administration within each operation. Evaluate the account's actual file write rights without opening a read-only file for replacement. No separate pathname-only verifier.
- [ ] **Complete protected writes.** In the commit invocation, reopen and verify the path and compare the expected snapshot before creating anything; keep directory pins for the operation. Create missing directories only under a verified parent. If creation changes the verified chain, recheck it and extend the baseline only with directories created and pinned by this operation. Create same-directory staging files exclusively with protected security descriptors before writing, flush, and recheck active identity, security, and bytes before replacing. Back up the previous bytes privately. Rename from the staged object within the pinned directory, without cross-volume copy. Keep the active ACL at least as restrictive as before. Refuse a changed or unverified target. Read back active bytes before returning a written snapshot; distinguish a proved precommit refusal from uncertain postcommit outcomes.
- [ ] **Wire the existing store.** `src/preferences-store.ts` dispatches Windows snapshots and commits only on a Windows host. Preserve decode/parse validation, changed-only edits, unknown members, safe reasons, and revision comparisons. Map managed/unknown administration to existing managed state and unverified active documents to existing invalid state. Do not return raw ACLs, raw helper errors, or snapshot bytes through RPC.
- [ ] **Verify GREEN.** Run `node --test tests/preferences-windows.test.ts tests/preferences-store.test.ts tests/preferences-runtime.test.ts tests/setup-service.test.ts` locally; require no failures. Require passing Windows store and RPC tests as a standard user, with no Windows safety tests skipped. Run two clients polling every `2000` ms for at least 30 seconds in the smoke test. Measure helper start and exit for the duration, not just after it: no more than two helpers alive during the two-client polling test, each poll returns before the next interval, and zero helpers remain when polling stops. Assert settings reads meet the existing `2000` ms setup wait and Save meets the `12000` ms deadline. If timing fails, fix it without skipping fresh ACL checks or expanding supported scope.
