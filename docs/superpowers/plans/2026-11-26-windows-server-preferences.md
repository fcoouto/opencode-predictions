# Native Windows Preferences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a native Windows OpenCode server safely read and save the existing `predictions.json` file.

**Architecture:** Keep the preferences store and TypeScript validation. Ship a precompiled Windows x64 .NET verifier that holds Win32 handles throughout each inspection or commit. Build one npm archive on Windows CI; the native jobs and release publish job use the same bytes.

**Tech Stack:** Node.js 26 for tests, TypeScript, .NET Framework, Win32, GitHub Actions, OpenCode V2 server `2.2.6`.

**Spec:** [`docs/superpowers/specs/2026-11-25-windows-server-preferences-design.md`](../specs/2026-11-25-windows-server-preferences-design.md)

## Global Constraints

- x64 Windows npm release, local, drive-qualified NTFS only; no directory aliases through symlinks or junctions. Keep `%APPDATA%`, explicit `XDG_CONFIG_HOME`, and `%ProgramData%` meanings. Fail closed for unverified input.
- Preserve the 65,536-byte limit, existing preference and RPC formats, server-side authorization, atomic replacement, private backups, and last-writer-wins risk. Do not add save locks, migrations, new dependencies, client changes, or POSIX changes.
- Launch the packaged verifier by fixed relative path, with no shell or install-time build. Keep code separate from request data, bound I/O, and propagate cancellation. Do not reuse completed ACL decisions.
- Use the macOS worktree for development and regression tests. Only native, non-admin Windows runs count for ACL and server qualification. If CI cannot run, leave Windows unqualified and report the blocker; do not weaken checks to make CI pass.

## Review Focus

1. Valid paths with spaces, apostrophes, square brackets, and non-ASCII characters must remain literal and round-trip.
2. A real user profile can inherit permissions to create unrelated siblings. A default profile must work without changing its directory ACLs.
3. Unsupported descriptors, an untrusted backup reader, and a writable parent with a read-only file must not get a permissive fallback.
4. Cancellation or lost helper output after commit dispatch must not be reported as a definite refusal or cause a retry.
5. An installed package needs the same helper as the source checkout, and two clients polling must not leave helper processes behind.

### Task 2: Add the Windows backend and prove file safety

**Files:** Add `src/preferences-windows.ts`, `src/preferences-windows.cs`, and `tests/preferences-windows.test.ts`. Modify `src/preferences-store.ts`, the native test harness, `scripts/build.mjs`, and the package and workflow files. No runtime script-file search, checked-in executable, or install-time build.

**Interfaces:** `readWindowsPreferences(source: string, systemPaths: readonly string[], signal: AbortSignal): Promise<WindowsSnapshot>` and `commitWindowsPreferences(before: WindowsSnapshot, systemPaths: readonly string[], next: Uint8Array, signal: AbortSignal): Promise<WindowsCommit>` from `src/preferences-windows.ts`. `WindowsSnapshot` is `{ source: string; state: "user" | "managed" | "unavailable"; writable: boolean; expected: string; bytes: Buffer; reason?: string }`. `expected` is a versioned digest of the source, verified directory identities and security, and active file identity, security, and bytes. For absence, bind the first missing component and the remaining path to the same verified directory chain; never use a constant missing-file revision. `WindowsCommit` is `{ kind: "written"; snapshot: WindowsSnapshot } | Exclude<PreferencesWriteResult, { kind: "written" }>`. `createPreferencesStore` still returns the existing interface and alone parses or edits the preference document. Only actual Windows takes the Windows I/O branch; keep simulated-platform path tests usable.

- [ ] **Implement handle-bound snapshots and commits in the fixed helper.** Use `CreateFileW` with `OPEN_REPARSE_POINT`; open directories with `BACKUP_SEMANTICS` and without delete sharing; walk from the validated local volume through one component at a time. ### Task 4: Simplify Windows Save after parity review

**Files:** `src/preferences-windows.cs` owns the write policy. `tests/preferences-windows.test.ts` covers it; `tests/host/windows-preferences.test.ts` verifies backup replacement. The README and Windows qualification record state the limit and new CI evidence. No RPC, Unix, packaging, or workflow changes.

**Interface:** Add a private `Session.CanReplace(Item file)` predicate. The caller still applies `Safe`, including its checks for detectable unsupported policy. `CanReplace` rejects read-only and encrypted files. Require exactly one applicable ordinary allow entry per server account, Local System, and built-in Administrators, each matching `Private(false)` after expanding generic rights. Allow `Inherited` as the only optional ACE flag. Refuse additional principals, denies, missing rights, and entries that do not apply to the file.

- [x] **Observe RED safely.** Add a native read-only case: create an ordinary active file via Save, add a benign extra read grant, then read settings. Expect `documentValid === true`, `writable === false`, and unchanged bytes and ACL. Do not run a Save on that custom file against the old verifier. [Native run 45779832107](https://github.com/fcoouto/opencode-predictions/actions/runs/45779832107) failed only the new eligibility assertion in both orders.
- [ ] **Simplify replacement.** In `Read`, compute `writable` from the already-open active file using `CanReplace` and retain the existing effective write check. Commit must require that decision from the same snapshot it checks for revision and bytes, before staging. Remove the second open that selected a replacement ACL, `NarrowAcl`, and its setter and write-ACL access right for staging. Active and backup stages keep their original private descriptor. When a backup would be replaced, inspect its descriptor and attributes before staging and retain the existing check before backup replacement. Refuse an encrypted or nonmatching backup; never widen it. Keep all existing active revision checks, directory pins, and postcommit readback.
- [ ] **Verify the defensive boundaries.** Use test-only inputs for the encrypted bit and for equivalent inherited/generic grants, a missing right, and an inapplicable entry. With the updated verifier only, assert custom active ACL Save returns `read_only` without changing bytes or ACL. For a narrower backup ACL, assert refusal before the pre-write staging checkpoint fires. Keep positive fixtures on the app-created private ACL and retain existing native safety tests. Add a third packaged Save and verify it replaces the backup with the second saved document. Both native jobs must pass Save, backup replacement, restart, and polling with no skips.
- [ ] **Document and verify.** State that simple private ACLs support repeat Save, unsupported permissions and EFS are read-only, and Save does not guarantee preservation of opaque audit metadata. Run `npm run check`, `npm run test:package`, and `git diff --check`. Record current native run evidence and independent review before changing PR readiness. Do not tag, merge, or publish.
