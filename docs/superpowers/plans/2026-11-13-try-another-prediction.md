# Try Another Prediction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, preserving the user's selected execution method. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users request another prediction from an untried model, current group first, using compact activity status while retaining the original internally for recovery.

**Architecture:** Extend the service's existing one-use offers with server-owned prediction-cycle progress, and return offers after real predictions as well as abstentions. Separate cached text, typed activity, alternative offers and pending identity in the controller/client. Reuse the existing shortcut and prediction slot in both hosts; temporarily replace the original with a non-adoptable compact status, not a persistent action or guidance block.

**Tech Stack:** TypeScript, Node test runner, OpenCode plugin SDK 2.2.6, existing Playwright/OpenTUI and native-host fixtures, existing esbuild/Vite scripts. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-13-try-another-prediction-design.md`

**Approved UX revision:** Fable's compact-status interaction supersedes this plan's earlier visible-original/Tab-cancels-replacement behavior. The user authorized implementation and relevant host tests, and subsequently requested the `￻` (U+FFFB) indicator prefix.

**Execution record:** Implemented with the latest faint abstention-placeholder revision and one independent review. All three material review findings were fixed with RED→GREEN regressions. Final checks: 204 unit/rendered tests, Desktop 10/10, CLI PTY 9/9, server 3/3, typecheck/build/package and whitespace checks passed. ## Global Constraints

- Route to the next untried eligible configured provider/model/variant in the current group's learned order before advancing to later groups. Never wrap to an earlier group within a cycle.
- Include actual ordinary-fallback calls in the cycle's tried set; selecting or displaying an offer does not count as a generation attempt.
- One additional generation call per explicit action. Text, valid abstention or error ends that action. Ordinary initial error fallback remains unchanged.
- Preserve `escalation: "off" | "manual" | "automatic"`, default `"manual"`, and `automatic` as the initial-trigger setting. Add no preference knobs.
- Automatic escalation makes at most one extra call after abstention using the new routing rule; it never automatically replaces valid prediction text.
- Immediately withdraw the original on `Alt+Shift+P`, retain it internally, and show only `￻▱▰▱ <Model Display Name>` while the alternative is pending. Restore the original on abstention/error/timeout.
- Initial generation shows only the indicator. Prefix indicators with `￻` (U+FFFB). Loop one filled block across three cells, never a percentage-like filling bar. Reduced motion uses static `￻…`, with the model name for alternatives.
- Tab passes through while status is visible; it cannot accept a hidden original or status, and does not itself cancel pending work. Acceptance resumes only for visible real text.
- Keep quota explanations in docs. Show shortcut guidance only in the faint no-prediction placeholder, not beside real predictions. This replaces advance per-action quota disclosure; cancellation does not guarantee avoiding provider charges.
- No button, including after abstention. No verbose pending generating/escalating sentences, extra progress line, elapsed counter or routine slow-wait message. After abstention without an original, show only `[<source display name>] provided no prediction.` and, when a target exists, `Use <shortcut> to escalate it to [<target display name>].` Render both as muted placeholder text, without changing composer dimensions. macOS labels use `Option+Shift+P`; others use `Alt+Shift+P`.
- Plugin-only communication is never inserted or submitted. Normal host Tab navigation and keyboard access remain intact.
- Preserve context filtering, configured reasoning, the 32,768-byte prompt budget, cancellation, stale-session/location checks, timeout/cooldown behavior and privacy boundaries.
- Implementation, isolated host tests, commits, PR delivery/merge and a local plugin update are authorized. Registry publication, unrelated configuration changes and paid prediction experiments are not authorized.

## Review Focus

1. Global queue promotion or cooldown recovery must not cause a candidate to repeat, or move the cycle back to an earlier group.
2. Two clients or rapid actions for the same context must not spend the same offer twice or silently restart a prediction cycle.
3. Tab during queued or active replacement must pass through without inserting the hidden original; stale outcomes cannot re-arm hidden text.
4. Typing must remove action authority without deleting cached real text merely because that text now also carries communication metadata.
5. Both hosts must display only compact pending status, disable hidden-text adoption, and restore originals on failure without leaking timers or duplicate activity announcements.

## File responsibilities and implementation choices

- `src/service.ts`: bounded cycle/offer authority, current-group-first selection, exact target validation and one-call execution. Reuse `candidateKey`, `skip`, `refresh`, `move` and the existing deadline guards; do not create a second ranking or health system.
- `src/rpc.ts`: preserve the existing `Request.escalation?: string` and `Reply.escalation?: EscalationOffer` contract. Offers may accompany text, abstention or a recoverable alternative error; they must not imply an extra model was already called.
- `src/controller.ts`: cache originals and offers, model typed activity independently, withdraw text while pending, restore on failure, and derive adoption solely from visible real text.
- `src/client.ts`: show pending intent before readiness awaits, translate outcomes, preserve queued token/epoch/version/draft guards, and distinguish generation readiness from adoption eligibility.
- `src/gui.ts`, `src/tui.ts`, `src/adapters/*`: replace persistent action/guidance with the compact status in the existing prediction slot, without confusing presentation with insertion payloads.
- Existing tests and synthetic host fixtures prove behavior; `README.md`, `src/feedback.ts` and tracked `dist/` describe and ship it. `src/options.ts` and `src/predict.ts` need no behavior changes.

**Builder decisions:** Use at most 128 in-memory cycles per service instance, matching the existing cache/offer bound; eviction invalidates associated tokens and an evicted continuation cannot generate. Each cycle is keyed by session/completion within the location-scoped service instance, with tried candidate identities, a monotonic current-group cursor and an in-flight reservation. In escalation-enabled modes, a repeated tokenless request for an existing cycle returns refreshed offer metadata without generation rather than restarting it. `off` retains ordinary refresh behavior. This also gives cancelled or expired actions a safe metadata-refresh path. No server-side cache of generated prediction text is needed; the existing client owns retained originals.

**Presentation decisions:** Keep `Communication.offer` as internal action authority even when no guidance is rendered. Add `type Activity = { kind: "initial" } | { kind: "alternative"; name: string }` in `src/controller.ts`, exposed through optional `Communication.activity?: Activity`; preserve existing host callbacks. Activity has no insertion payload. Host adapters render frames from the existing client tick and a 200 ms clock phase, without new animation timers or entry/exit motion. Use a 1,500 ms transient **No alternatives available.** outcome. Reduced motion is static; CLI reads existing animation preferences, not a new setting. See the execution ledger for the upstream retry limitation discovered by host tests.

**Execution amendments:** Final review requires explicit metadata-only continuation intent (`Request.escalation: "refresh"`), bounded readiness/refresh waits, and keyed offer revocation when typing is observed between polls. Reserved refresh intent uses the existing string field; older services reject it without generation. Latest user feedback requires optional `Reply.modelName?: string` plus its RPC output schema field for authoritative source display names. This is the only additive wire field. Render the exact two-line abstention copy above with no button, matching prediction opacity and unchanged composer height; direct Desktop input events dismiss the overlay before the polling tick. All changes require RED→GREEN regression proof and fresh relevant host gates.
